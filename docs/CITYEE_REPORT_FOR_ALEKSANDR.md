# CityEE — отчёт по аналитике лидов и что нужно сделать в GTM/GA4/Ads

**Кому:** Александр (доступ к GA4 / GTM / Google Ads)
**Дата:** 08.09.2026
**Контейнер:** `GTM-5DRRX5ZJ` (cityee.ee), опубликованная версия **11 «last»** (04.08.2026)
**Статус:** найден **доказанный дефект конфигурации в GTM**, из-за которого лиды считаются неверно.
Код сайта уже исправен — оставшийся фикс полностью на стороне GTM (+ один снимок Consent Mode).

---

## 1. Зачем это всё (цель)

Для CityEE нужно, чтобы **одна отправка формы = одна конверсия лида** в GA4 и в Google Ads, без
дублей и без ложных срабатываний, и чтобы **клики по WhatsApp/телефону/Telegram/почте НЕ считались
формами-лидами**. На этом строится оптимизация Google Ads: если конверсия «замусорена», реклама
учится на неправильном сигнале.

## 2. Итог одним абзацем

По твоим же скриншотам видно: тег, который шлёт в GA4 событие `generate_lead`, срабатывает по
**`lead_submit_success`**, а сайт при отправке формы шлёт **`generate_lead`** — и триггера на
`generate_lead` в контейнере **нет**. Плюс **два** тега шлют `generate_lead` на один триггер (дубль),
и ещё один тег шлёт `generate_lead` **на каждый просмотр страницы**. Итого: реальные заявки с форм
могли не считаться, а то, что считалось, — задвоено и частично приходило от кликов по контактам.
Всё чинится в GTM за 3 действия, без изменения сайта, SEO, кампаний, ставок и бюджетов.

## 3. Что проверено (текущее состояние — мы ничего не меняли)

- **GA4 (ресурс cityee.ee):** ключевое событие одно — `generate_lead`. Поток данных **`G-569W1W9H0W`** (у тега Google также ID `GT-M3VG7CDZ`). Событий `lead_form_submit` / `lead_submit_success` в этом ресурсе нет.
- **В контейнере всплывает второй ID `G-56M1W9H0W`** — «фантомный», на него ссылается только сломанный тег (см. F2).
- **Google Ads (общий аккаунт ADME):** конверсия CityEE — **`cityee.ee (web) generate_lead`**: источник GA4, **Основная (Primary)**, счёт **«Одна конверсия»**, событие `generate_lead`. Это правильно. Остальные Primary в цели «Submit lead form» относятся к **другим** бизнесам аккаунта (Positum, Coralclean, adme), не к CityEE.
- **Теги (7), триггеры (4), переменные (2)** — разобраны ниже.

## 4. Что не так (проблемы)

| # | Что нашли | Почему это плохо |
|---|---|---|
| **F1** | **Два** тега шлют `generate_lead` на один триггер `lead_submit_success`: «👉 GA4 – generate_lead (Form Submit)» и «GA4 - G-56M1W9H0W». | Каждое срабатывание = **два** события `generate_lead` → задвоение лидов в GA4/отчётах. |
| **F2** | Тег **«Google Analytics Configuration»** — это на самом деле GA4-**событие** `generate_lead`, триггер **All Pages** (каждый просмотр), поток фантомный `G-56M1W9H0W` (с ошибкой «нет тега Google»). | Сейчас, скорее всего, не отправляет (фантомный ID), но это мина: если такой поток создадут — **каждый просмотр станет лидом**. |
| **F3** | Единственный триггер лида — `lead_submit_success`, а сайт при отправке формы шлёт `generate_lead`. Триггера `generate_lead` в контейнере нет. | **Реальные заявки с форм могут не считаться вообще** (это и есть причина «форма отправилась — события нет»). |
| **F4** | Клики по контактам (тел/WhatsApp/Telegram/почта) на сайте шлют `lead_submit_success`, а лид-теги как раз на него и срабатывают. | Клики по контактам засчитываются как формы-лиды (и задвоены). *На сайте это уже переименовано; выкатим после действия B.* |
| **F6** | Ни на одном лид-теге не проброшен параметр `event_id` (сайт его отдаёт). | Не работает дедупликация GA4↔Ads по `event_id`, которую мы заложили. |
| **F7** | В контейнере не видно Consent Mode / CMP; в коде сайта его тоже нет. | Нужно подтвердить, учитывается ли согласие. Пока просто снимок — ничего не меняем. |
| **F8** | Google Ads: единственная Primary-конверсия CityEE `cityee.ee (web) generate_lead`, счёт «Одна». | ✅ Это правильно. Менять не нужно (зависит только от фикса F1/F6). |

> Важно: скриншоты доказывают **конфигурацию**, а не факт срабатывания в реальном времени. Точный
> масштаб (сколько именно задвоено / считались ли формы) подтвердим в **DebugView** при проверке.

## 5. Что нужно сделать в GTM

Работаем в рабочей области, затем **Предварительный просмотр**, затем **Отправить**. Один набор
изменений, одна публикация. Всё — **только текущее состояние читаем, меняем перечисленное**.

### ДЕЙСТВИЕ A — убрать дубль и опасный тег
1. Менеджер тегов → cityee.ee → **Теги**.
2. Открыть **`GA4 - G-56M1W9H0W`** → ⋮ (справа вверху) → **Приостановить** (или **Удалить**). *(убирает второй отправитель `generate_lead` — F1)*
3. Открыть **`Google Analytics Configuration`** → ⋮ → **Приостановить** (или **Удалить**). *(убирает `generate_lead` на всех страницах и ссылку на фантомный `G-56M1W9H0W` — F2/F5)*
- **PASS:** ровно один тег шлёт `generate_lead`; ни один не шлёт его на All Pages.

### ДЕЙСТВИЕ B — привязать лид к отправке формы и пробросить `event_id`
1. **Переменные** → «Переменные, определяемые пользователем» → **Создать** → тип **Переменная уровня данных** → имя `event_id`, имя переменной уровня данных `event_id`. Сохранить. *(по желанию так же `form_type`, `source_class`)*
2. **Триггеры** → **Создать** → тип **Специальное событие** → название события `generate_lead` → «Все специальные события» → имя триггера `generate_lead`. Сохранить.
3. **Теги** → открыть **`👉 GA4 – generate_lead (Form Submit)`**:
   - В блоке **Триггеры** убрать `lead_submit_success`, добавить новый триггер **`generate_lead`**.
   - В блоке **Параметры события** → **Добавить параметр**: `event_id` = `{{event_id}}` *(по желанию `form_type`={{form_type}}, `source_class`={{source_class}})*.
   - Проверить: поток данных **`G-569W1W9H0W`**, событие `generate_lead`. Сохранить.
- **PASS:** лид-тег срабатывает на специальное событие `generate_lead` и содержит параметр `event_id`.

### ДЕЙСТВИЕ C — снимок Consent Mode (ничего не меняем)
1. **Администрирование → Настройки контейнера** → включить **«Обзор согласований»**.
2. В **Тегах** появится столбец согласия — скрин.
3. Если есть тег CMP/Consent Mode — скрин его настроек. Если нет — напиши: «Consent Mode отсутствует».

## 6. Проверка перед публикацией (GA4 → Отладка / DebugView)
Открой **Предварительный просмотр** (Tag Assistant) на cityee.ee и GA4 **DebugView**:
1. **Отправка формы** (обычный заход, без `gclid`) → в DebugView **ровно один** `generate_lead`, с `event_id`, **без** имени/телефона/почты/сообщения.
2. **Клик по WhatsApp/Telegram/телефону/почте** → `generate_lead` **НЕ** появляется.
3. Если п.1–2 выполнены → **Отправить** (назвать версию, напр. `X9995: single generate_lead + event_id`).

## 7. Что НЕ трогать
- Теги `contact_mail` / `contact_telegram` / `contact_whatsapp` и их триггеры.
- Базовый тег `Ter Google` и поток `G-569W1W9H0W`.
- Google Ads: кампании, ставки, бюджеты, ключевые слова, атрибуцию, импорт; другие бизнесы аккаунта (Positum, Coralclean, adme).
- SEO, контент, тексты, структуру страниц.

## 8. Что дальше (последовательность)
1. Ты применяешь **A + B (+ C)**, проверяешь в DebugView, публикуешь.
2. Присылаешь Николаю скрины: DebugView (форма = 1× `generate_lead` с `event_id`; клик = 0×) и «Обзор согласований».
3. **После** этого CityEE выкатывает изменение сайта (клики по контактам переименованы на `contact_link_click`, чтобы больше не попадать в лид). Порядок важен: сайт — только **после** действия B.
4. Затем — контроль 72 часа и решение по Consent Mode.

**Итог:** реализация на сайте корректна; единственная блокирующая правка — эти действия в GTM.
После них одна отправка формы = одна конверсия `generate_lead` с `event_id`, а клики по контактам
перестанут считаться формами.
