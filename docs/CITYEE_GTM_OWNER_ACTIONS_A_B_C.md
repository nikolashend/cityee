# CITYEE — GTM OWNER ACTIONS (для Александра)

**Контейнер:** `GTM-5DRRX5ZJ` (cityee.ee) · **опубликованная версия сейчас:** 11 «last».
**Цель:** одна авторитетная конверсия лида `generate_lead`, срабатывающая ТОЛЬКО на отправку формы,
с параметром `event_id`. Убрать дубли и ложные срабатывания.

**Правила безопасности (обязательно):**
- Текущее состояние уже зафиксировано (скриншоты). Работаем в рабочей области, потом Предпросмотр, потом Отправить.
- **Не менять** SEO, контент, другие сайты в аккаунте, кампании/ставки/бюджеты Google Ads.
- **Не трогать** теги `contact_mail` / `contact_telegram` / `contact_whatsapp`, базовый тег `Ter Google`, поток `G-569W1W9H0W`.
- Всё делаем **в одном наборе изменений**, публикуем один раз, с понятным названием версии.

---

## ДЕЙСТВИЕ A — убрать дубли и опасный тег

**A1. Дубликат отправителя `generate_lead`:**
1. Менеджер тегов → cityee.ee → слева **Теги**.
2. Открыть тег **`GA4 - G-56M1W9H0W`** (тип «Google Аналитика: событие GA4», событие `generate_lead`, параметры lead_type/lead_source, триггер `lead_submit_success`).
3. Правый верхний ⋮ → **Приостановить** (или **Удалить**).
   - *Почему:* этот тег и тег «👉 GA4 – generate_lead (Form Submit)» шлют ОДНО и то же событие `generate_lead` на один триггер → двойной счёт.

**A2. Тег, шлющий `generate_lead` на КАЖДЫЙ просмотр страницы:**
1. Открыть тег **`Google Analytics Configuration`** (тип GA4-событие, событие `generate_lead`, поток `G-56M1W9H0W`, триггер **All Pages**, с предупреждением «нет тега Google / undefined»).
2. ⋮ → **Приостановить** (или **Удалить**).
   - *Почему:* базовый конфиг не должен слать `generate_lead`; тут он шлёт лид на каждый page view на «фантомный» поток `G-56M1W9H0W`. Если этот поток когда-нибудь создадут — каждый просмотр станет лидом (катастрофа).

**PASS A:** в списке тегов ровно ОДИН тег шлёт `generate_lead` («👉 GA4 – generate_lead (Form Submit)»); ни один тег не шлёт `generate_lead` на All Pages.
**FAIL A:** остаётся второй generate_lead-тег или тег на All Pages.

## ДЕЙСТВИЕ B — привязать лид к отправке формы и пробросить event_id

**B1. Переменная event_id:**
1. Слева **Переменные** → блок «Переменные, определяемые пользователем» → **Создать**.
2. Тип: **Переменная уровня данных**. Имя переменной: `event_id`. Имя переменной уровня данных: `event_id`. Сохранить.
3. (по желанию так же создать `form_type` и `source_class`.)

**B2. Новый триггер `generate_lead`:**
1. Слева **Триггеры** → **Создать**.
2. Тип: **Специальное событие**. Название события: `generate_lead`. Условие: «Все специальные события». Имя триггера: `generate_lead`. Сохранить.

**B3. Перенастроить единственный лид-тег:**
1. **Теги** → открыть **`👉 GA4 – generate_lead (Form Submit)`**.
2. Блок **Триггеры**: убрать `lead_submit_success`, добавить новый триггер **`generate_lead`** (из B2).
3. Блок **Параметры события** → **Добавить параметр**:
   - Параметр `event_id` = `{{event_id}}`
   - (по желанию) `form_type` = `{{form_type}}`, `source_class` = `{{source_class}}`
4. Убедиться: поток данных = **`G-569W1W9H0W`**, событие = `generate_lead`. Сохранить.

**PASS B:** лид-тег срабатывает на специальное событие `generate_lead` и содержит параметр `event_id`.
**FAIL B:** тег остался на `lead_submit_success`, или `event_id` не проброшен.

## ДЕЙСТВИЕ C — зафиксировать состояние Consent Mode (только снимок, ничего не менять)
1. **Администрирование → Настройки контейнера** → включить показ **«Обзор согласований»** (Consent Overview) в списке тегов.
2. Вернуться в **Теги** — у каждого тега появится столбец согласия. Сделать скрин.
3. Если есть тег CMP / Consent Mode — открыть и сделать скрин настроек. Если такого тега нет — так и написать: «Consent Mode в контейнере отсутствует».
   - *Зачем:* нам нужно понять, учитывается ли согласие в GA4/Ads. Пока НИЧЕГО не меняем.

## ПРОВЕРКА (обязательно перед публикацией) — GA4 DebugView / Предпросмотр
Открыть **Предварительный просмотр** (Tag Assistant) на cityee.ee и параллельно GA4 → **Отладка (DebugView)**:

1. **Реальная отправка формы** (обычный заход, БЕЗ `gclid`): в DebugView должен появиться **ровно один** `generate_lead`, с параметром `event_id`, **без** имени/телефона/почты/сообщения.
2. **Клик по WhatsApp/Telegram/телефону/почте:** событие `generate_lead` **НЕ** появляется (появляются только contact_*).
3. **Тестовая отправка с `?gclid=CITYEE_TEST_QA`:** `generate_lead` **НЕ** появляется (подавление теста; заметьте — сработает только после того, как на сайте задеплоят website-часть, но подавление теста уже реализовано на сайте).

Если п.1–2 выполняются → **Отправить** (Submit), назвать версию, например `X9995: single generate_lead + event_id`. Затем прислать Николаю скрины DebugView (п.1, п.2) и Consent Overview (Действие C).

## Что это исправляет
- **F1** дубль generate_lead (A1) · **F2** generate_lead на всех страницах (A2) · **F5** фантомный ID (A1/A2)
- **F3** формы не считались, т.к. триггер был `lead_submit_success`, а сайт шлёт `generate_lead` (B2/B3)
- **F6** проброс `event_id` для дедупликации GA4↔Ads (B1/B3)
- **F4** после B клики по контактам перестают попадать в лид-тег автоматически; на сайте отдельно переименуем событие клика (деплой ПОСЛЕ действия B)
- **F7** снимок Consent Mode (C)
